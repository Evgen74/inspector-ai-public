# «Инспектор ИИ» — релизная памятка (день сдачи)

Состояние: M1 + сборка M2 за день сдачи. Локальный запуск, без Docker, без сетевых вызовов в продукте.

## 1. Как запустить

Требуется: PostgreSQL 17 (:5432, БД `inspector`), Redis (:6379). RabbitMQ (:5672) необязателен: без него задания идут в процессе API (режим `in-process`), с ним — через очередь `inspector.jobs`.

| Что | Команда |
|---|---|
| Установка и базовый тест | `make setup && make test` (pytest 4 воркера, vitest web/api, контракты, guard) |
| Линт | `make lint` |
| Миграции БД | `make db-migrate` (в т.ч. `0006_tz_modules_a.sql`) |
| Демо-учётки | `make db-seed` |
| Весь стек | `make dev` (API :3000, web :5173, ml-api :8090) или по отдельности `make api-dev`, `make web-dev`, `make ml-api-dev` |
| Сквозной прогон обучающего объекта | `make run-train OBJECT=OBJ-TYUMENSKAYA-5-GOLD-SEED RUN_ID=<id> ARGS="--from-step recognize --workers 2"` |
| Оценка | `make score PRED=runs/<id>/submission` |
| Гейт T-GOLD | `make score-selftest` |

Важно: `--from-step layout` на новом `RUN_ID` даёт деградированную разметку (нет каталога `tokens/`); стартуйте с `recognize` (кэш, около 5 с) или передайте `--tokens-run`.

Веб: http://127.0.0.1:5173. Метрики Prometheus: http://127.0.0.1:3000/metrics (публично, вне `/api/v1`).

Демо-учётки (пароль по умолчанию `Demo-Inspector-2026`, переменная `INSPECTOR_DEMO_PASSWORD`): одна учётка `inspector` («Иванова Мария Сергеевна»). В продукте одна роль — «Инспектор» (`INSPECTOR`), суперроль со всеми правами (решение владельца продукта от 29.09); остальные роли удалены. Миграция `0008_single_inspector_role.sql` переводит существующих пользователей БД в эту роль (`make db-migrate`).
Финализация и отмена финализации протокола: доступны инспектору без ограничения по назначению объектов, нужен повторный ввод пароля (`/auth/reauth`) и `If-Match`; отмена — с причиной (≥ 20 символов). Разделения ролей нет (решение владельца продукта 29.09: одна учётка `inspector`, одна суперроль).
Локально `INSPECTOR_AUTH_MODE=optional` пропускает запросы без сессии на чтение; изменяющие запросы требуют сессию и CSRF.

## 2. Где получается сдаваемый ответ

Обучающие объекты: `runs/<run_id>/submission/<OBJECT>.json` (полный ответ), строгий вариант и sidecar рядом, протокол по Приложению 2 в `runs/<run_id>/protocol/`.
Скрытый объект: **решением руководителя (29.09, 10:53) не обрабатывается и ответ по нему не сдаётся**; распознавание остановлено на 4476 из 15678 страниц (кэш сохранён), объект в архиве веб-интерфейса. Порядок, если к нему вернутся: только по одному замороженному прогону, шаги `recognize`, `layout`, `tables`, `compare`, `export` отдельными командами `inspector-batch` с флагом `--hidden-run` (команда `run` на нём отказывает, `score` тоже). Идентификатор объекта берётся из `split_policy.json` и в коде не хардкодится. Итоговый файл: `runs/<hidden-run-id>/submission/…`. До отправки никто не смотрит его содержимое и результаты (правило 4 CLAUDE.md).

## 5. Известные ограничения

- Правки в «Нормативной базе» (`min_value`, `max_value`, `is_active`) применяются в прогонах: `inspector_common.params.load_params()` читает `.cache/matrix_overrides.json` (или файл из `INSPECTOR_MATRIX_OVERRIDES`, значение `off` отключает), версия Матрицы получает суффикс `+ovr.N` в протоколе, sidecar и `run_context`, хэш переопределений входит в `config_hash`. Отключённый параметр не даёт находок и остаётся строкой `NOT_APPLICABLE` / `PARAM_DEACTIVATED` (132 строки сохраняются). Скрытый прогон (`--hidden-run`) принудительно отключает переопределения и записывает `disabled_by_env`. Пороги попадают только в правила с границами; компараторов границ (`OUTSIDE_BOUNDS`) в сравнении пока нет, поэтому изменение порога без нового компаратора находки не меняет.
- Не построены: компаратор допусков ИГС (нет данных для проверки), АР (площади, ширины дверей) и ГП (ТЭП) PD↔RD, спецификации ЭОМ/ВК. Глубина по скрытому объекту поэтому ограничена КР/КЖ↔ИД.
- Извлечение толщин шумное; используется только PD→RD и только когда все значения РД ниже всех значений ПД. Выбор конструктивных файлов ПД/РД по имени (регулярка) — эвристика; файлы с другими именами будут пропущены.
- Локации КР/FREE-STRUCTURE — названия семейств («Сваи»), а не обозначения элементов из акта; совпадение с золотом по локации не гарантировано.
- Оценка Тюменской: ложное срабатывание IOS4-078 · 002 устранено (причина: правило соседства номера помещения перебивало выноску; теперь оно не действует, если марка лежит в зоне другого помещения). Контрольный прогон `runs/ag02b-fix3`: 100/100, 10/10, 0 FP; финальный прогон `final-tyumen` не пересобирался.
- Правило соседства марки и номера помещения проверено только на Тюменской.
- Идентификаторы загруженных файлов `U<8hex>-<n>` (расширен `ManifestFileId`), а не `U0001`. `ProcessStatus` теперь содержит `FAILED`; новые статусы стадий загрузки в `enums.yaml` не вынесены.
- OpenAPI всех модулей влит в `packages/contracts/openapi/openapi.yaml` (файлы `apps/api/openapi/pending/*.yaml` оставлены как идентичные копии, слияние их пропускает); `x-audit-action` для РиН и самопроверки: `RIN_SYNC_REQUESTED`, `RIN_SYNC_RESULT`, `SELFTEST_RUN` (добавлены в `AuditAction`). Таблицы `params_overrides`, `matrix_versions`, `rin_deliveries`, `rin_attempts` — только SQL, без Drizzle-схемы.
- `rbac.yaml`: все права выданы единственной роли INSPECTOR (scope ALL).
- Архивирование («Архивировать», M2 backlog п. 6): `POST /admin/objects/{id}/archive`, `/admin/batch-runs/{id}/archive`, `/processes/{id}/archive` (право `batch.import`, тело `{"archived": false}` возвращает элемент). Архивные скрыты в списках и на дашборде; `include_archived=true` показывает их. Миграция `0007_archive.sql` (`make db-migrate`). В dev-БД заархивированы `OBJ-UPLOAD-7de7f69f`, прогоны `m1-ag00-import-smoke`, `d1-fixture-tyumen`. В интерфейсе кнопка есть на «Проверках» (с переключателем «Показать архивные») и на «Объектах»; возврат объекта и прогона из архива только через API. Аудит пишется как `HTTP_POST` (кода действия в `enums.yaml` нет).
- Загрузка: адрес из формы записывается в карточку объекта после импорта; загруженные файлы не чистятся (`runs/uploads/`); число процессов распознавания задаётся `INSPECTOR_UPLOAD_WORKERS` (по умолчанию 8 на M2 Max; на общей машине уменьшить).
- Самопроверка: проверки, зависящие от сессии администратора и состояния процессов, помечаются «Пропущена», если запустить без входа. Показатель памяти на macOS ориентировочный.
- Веб-интерфейс автоматически проверен только vitest; на живом браузере в день сдачи все пункты меню руками не пройдены (подключение к Chrome CDP недоступно).
- Тест `inspector_registry::test_shared_inode_with_different_hashes_is_ambiguous` один раз падал под xdist и проходил отдельно (возможная нестабильность).
- Запуск API из песочницы Claude не видит PostgreSQL (`/health` = 503); запускайте `make api-dev` из обычного терминала.
